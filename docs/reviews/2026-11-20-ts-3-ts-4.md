## 需求方決定

### D1. TS-3 AI 摘要的權限實際只由 `netops.ai.use` 控管

- 計畫書 §5.3 與提示詞寫「權限綁 `netops.ai.use` + `netops.pa-signature.read`」。實作沿用 `POST /v1/ai/explanations`(`x-permission: netops.ai.use`),新增 `kind: pa-signature`。
- 原因:Gateway 每條路由只綁一個 `x-permission`,`X-Internal-Token` 不帶完整權限清單,後端無法同時檢查兩個代碼(TS-2 的 Q8 也因此把含 IP 的命中查詢拆成獨立路由)。
- 影響:有 `netops.ai.use`、沒有 `netops.pa-signature.read` 的人,可以直接呼叫 API 拿到特徵碼 AI 摘要。畫面上的 AI 分頁仍依 `netops.pa-signature-page.ai` 按鈕權限顯示。
- 送出內容只有特徵庫公開欄位(ID、名稱、等級、CVE、預設動作)與統計(App 排行、命中筆數、動作分布、規則缺口**條數**),不含 IP、姓名、規則名稱。
- 建議:**比照 PR-5(需求方 2026-11-19 決定 AI 判讀只有 `netops.ai.use` 也能用)接受現狀**,不改。若要嚴格綁兩個代碼,需改成獨立路由(例如 `x-permission: netops.pa-signature.read` 的 AI 端點),但那樣又少了 `netops.ai.use` 的檢查,同樣只能綁一個。

## 已確認(通過)

### TS-3(!168)

1. **只送統計**:`pa-signature/ai.ts` `buildSignatureAiContext` 只組特徵公開欄位與統計;命中動作分布查詢強制 `includeIps: false`;規則只傳缺防護的**條數**(`unprotectedRuleCount`),不傳規則名稱;不附 IP 對照表與知識庫。單元測試 `pa-signature-ai.test.ts` 驗證送出內容無 IP / 姓名 / 原始 log。
2. **前 50 筆**:`pickHighRiskSignatures` 依「有命中 → critical > high → 命中數 → ID」排序,截斷時明確告知總數與未列筆數(§5.3)。
3. **降級不回 5xx**:ClickHouse(命中、App 排行、動作分布)、安全規則快照各自失敗回 `null` 並在文字與 SSE `meta`(`hitsAvailable`、`appsAvailable`、`coverageAvailable`、`partial`)標示;無快照回 404 / 424 `NETOPS_PA_SIGNATURE_UNAVAILABLE`。
4. **限制要講明**:基準版本、歷史不足(`since`)、索引重建(`rebuilt`)、快照過期(`stale`)都寫進送給模型的資料並要求回答說明,不把沒有資料當 0(AGENT §5)。
5. **參數**:`days` 只接受 7 / 30 / 90(schema enum + service 再檢查)。`topApps` 用 `query_params`、限 1–200 筆,讀每小時 App 彙總表。
6. **提示詞**:資料區塊內文字聲明為資料不是指示(防特徵名稱夾帶指令);不輸出 PA 指令;免責只在開頭(同 PR-5 決定)。

### TS-4(!169)

1. **TS-2 審查結論 5 項都已落實**:`firstVersion` null 顯示「未知」、`rebuilt` 顯示「這一版差異無法計算」、`since` 顯示「自 YYYY-MM-DD 起統計」、IP 只依後端 `includeIps` 顯示(`SignatureHitsTab` `showIps`)、查無 ID 走 202 lookup 並顯示「本機特徵庫查無…」。

3. **戰情室**:`mergeNewSignatureHits` 合併 WR-1 / WR-2,同 ID 取較大筆數不重複加總;提示列不含 IP。
4. 只改前端,無後端、RBAC、部署設定變更。
