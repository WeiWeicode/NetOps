## 3. 失敗與未驗項目

### 3.1 Log 明細查詢送出:回 404(預期的明確錯誤,功能本身未驗到)
- 步驟:V112001 登入 → `/netops/firewall/search` → 開始 `2026-11-03 10:00`、結束 `10:05`、目的 Port `443` → 查詢。
- 實際:`POST /api/netops/pa/log-searches` 回 404,畫面顯示「查詢失敗:啟用時間沒有已分析的 log 檔,請先到『FTP Log 檔案』同步」(requestId `d430ed7dced1`)。
- 判斷:符合 AGENT §5(明確回報資料不完整、不回傳看似正常的空結果)。原因是測試區目前沒有已分析的 TRAFFIC log(流量總覽顯示「尚未分析任何 PA log」,只有威脅、URL 過濾、資料過濾、WildFire 有資料)。
- 影響:Log 明細查詢的背景工作、結果表、匯出(含 viewer 匯出權限)都沒有驗到。
- 需要:在測試區分析至少一個 TRAFFIC 檔(`netops.pa-files.manage`,寫入操作,需 admin 並先取得同意)後重驗。

## 4. 發現的問題與可能原因

### 4.1 安全事件頁無資料時仍呼叫 API 並回 400(已由 `fix/netops-pa-events-no-days` 處理,待部署後重驗)
- 步驟:netops-admin 開 `/netops/firewall/events`(測試區尚無任何已分析 PA log 時)。
- 實際:`GET /api/netops/pa-events/overview?type=threat&top=15` 回 400 `VALIDATION_FAILED`,details `must have required property 'from'`(requestId `db74fbae…`、`89e9978b…`)。頁面本身顯示正確的空狀態,但 `netops-api` 的 4xx 紀錄累積(架構觀測「4xx」內該 API 5 筆)。
- 推測原因:沒有已分析日期時前端沒帶 `from`,後端把它當必填。
- 狀態:`develop` 已合併 `fix/netops-pa-events-no-days`;測試區是否已部署未核對。
- 影響:只造成錯誤紀錄,不影響使用。

### 4.2 權限指派被防提權擋下(Gateway 行為,已轉主串處理)
- 步驟:IT 管理 › 人員與部門 › 個別指派 `netops-admin` / `netops-viewer` 給 S112009、V112001。
- 實際:儲存回 403 `PERMISSION_DENIED`「不可指派或移除含有您沒有的權限的角色」,details 列出 `netops.app.access`、`netops.pa-*`、`netops.ad-*`、`netops.kb-page.*`、`netops.kb.*`、`netops.pa-log.read` 等(requestId `474caec6c9d6`、`ceec53f51f51`)。
- 原因:`giga-api-gateway-bff/bff/src/modules/admin/users.ts` 第 296–315 行,新增或移除的角色其權限(含選單隨附的 API 權限)須是操作人本身具備;`gw-super-admin`、`it-admin` 沒有 `netops.*`。
- 處理:決定用 Gateway CLI `apply` 把 `netops.*` 補進 `gw-super-admin`(不改檢查規則);之後指派成功(PATCH 回 200)。
- 建議:每個新應用上線,「補管理者權限」要列為上線步驟(`gateway-rbac.yaml` 的 `apply` 順序),否則同樣會卡住。

### 4.3 `/netops/` 一度進得去、隨後又被導回入口網(原因未明,後來沒再重現)
- 順序:S112009 先被導回(無權限)→ 使用者指派後 `/netops/` 可進(admin 畫面完整)→ 之後「權限試算」顯示 S112009 只命中 `employee`、`gw-super-admin`、`it-admin`,`/netops/` 又被導回入口網。
- 推測:權限快照(`perm_version`)與實際指派的時差,或指派曾被收回。未能確認。
- 後續:權限補齊並重新登入後,V112001 可正常使用;建議指派後再觀察一次是否再發生。
- 另:被導回時網址在我讀取時已是 `/`,未讀到 `?denied=netops`。

## 5. 觀察到的風險

1. **FTP 根目錄列出系統資料夾**:`$RECYCLE.BIN`、`System Volume Information` 出現在 FTP Log 檔案清單。建議前端或後端過濾。
2. **viewer 開 AD 的 FTP Log 檔案頁就會觸發 FTP 掃描**:頁面載入自動送 `POST /api/netops/ftp/ad/listings`(202),顯示「正在列出 FTP 上的日期資料夾(最長 3 分鐘)」。唯讀角色也會觸發 FTP 工作,且 3 分鐘內多人開頁可能疊加(AGENT §6:FTP 同時連線 1)。
3. **知識庫備份是空的**:`LAST_RESULT` 為 `OK netops-kb-test-20261104.tar.gz files=0 size=4.0K`,tar.gz 僅 97 bytes,因為測試區知識庫目前 0 則筆記。備份容器沒有 healthcheck,只能靠 `LAST_RESULT` 判斷;建議等有筆記後確認備份內容可還原。
4. **架構觀測 `netops-web` 顯示 4 筆錯誤**:只翻到 4xx 清單第一頁,未確認是哪幾筆;其中可能含驗收期間我自己對 `/netops/assets/` 的探測(403)。
5. **瀏覽器 console**:`/netops/assets/index-eJBfJ8Yi.js` 的 `Uncaught (in promise) Error`(3 筆)出現在無權限被導走時;另有 `ERR_BLOCKED_BY_CLIENT`、`wss://…/ws/notify` 連線失敗、一筆 `api/notify/feed` 502,屬入口網 / IT 管理頁,非 NetOps。
6. **viewer 可匯出明細**(HANDOFF 待決定項目已列):因 Log 明細查詢未驗到,匯出行為待重驗。
7. **PA 與 AD 的 FTP 管理按鈕共用 `netops.ftp.write`**(HANDOFF i):viewer 驗證中兩處按鈕皆隱藏,但單獨指派按鈕時權限會比預期大。
8. 測試區 `gno-backend` 啟動 log 有 MongoDB `ECONNREFUSED` 重試訊息,之後 topology 正常載入,未確認是否已穩定重連。
