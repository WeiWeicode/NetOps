### 新增單元測試涵蓋範圍（`pa-collector/tests/test_signatures.py`）

1. **`show system info` 與發布時間正規化**：驗證 `threatVersion`、`appVersion`、`avVersion`、`wildfireVersion`、`urlFilteringVersion` 與 CST（`+08:00`）/ UTC（`Z`）ISO 8601 時間轉換。
2. **特徵正規化（依 TS-0 實測欄位）**：弱點（`vulnerability`）與間諜軟體（`phone-home`）依數字 ID 排序、截斷 `MAX_TEXT=1024`、`affected-host`（文字與子節點）、`default-action` 子節點名稱、`cve` / `vendor` 清單、`disable` 旗標、`time-attribute` 保留原樣、非數字 ID 略過。
3. **vsys1 Profile Group 與 VP / AS Profile 解析**：`profile-group` 欄位對映與 `policies.py` 一致；VP / AS profile 只取第一層 `<entry>`，不混入巢狀 `rules` / `threat-exception` / `botnet-domains` 的 `<entry>`。
4. **唯讀白名單（`op` 與 `call` 雙重強制）**：拒絕 `type=config`、`type=log`、多餘參數、`shared/*`、`request`、非數字 / 超長 / 含換行字元或 XML 注入的 `show threat id`。
5. **版本比對與增量跳過**：首次無快照抓全清單（含開頭及讀弱點／間諜軟體前各查一次 CPU，共 9 支 op）；`threat-version` 未變時只送 `CPU_CMD` + `INFO_CMD`（2 支 op），同步更新 `avVersion` / `wildfireVersion` / `checkedAt` 並續期 TTL、保留 `fetchedAt` 與 `baselineAt`；`threat-version` 變更時重抓全清單並保留 `baselineAt`。
6. **手動重新整理與冷卻**：`netops:pa:sig:refresh` 強制全清單重抓；距上次執行未滿 `MIN_MANUAL_SEC`（60 秒）保留鍵不消耗。
7. **CPU 保護、二次／三次重檢（S1）與暫停、心跳反映（S2）**：開頭、讀 `VULN_CMD` 前、讀 `SPYWARE_CMD` 前管理平面 CPU 讀不到或 > 50% 均標記 `rejected`、不送清單並保留上一份快照；`paused=True` 完全不送 PA 請求並於 60 秒後重檢；`self.status` 心跳以 `signatureState` / `signatureStateAt` / `signatureNote` 明確呈現 `ok` / `rejected` / `paused` / `failed`，其中 `rejected` 與 `paused` 視為正常保護退讓／手動暫停而不寫 `signatureError`（避免誤報故障）。
8. **失敗保留上一份快照與上限防護**：空弱點清單、空間諜軟體清單、超過 `MAX_SIGNATURES`、超過 `max_bytes` 均標記 `failed` 且保留既有 Redis 快照；錯誤 API Key 訊息遮罩且不外洩、金鑰僅放在 `X-PAN-KEY` 標頭。
9. **可選 profile 節點 `No such node`**：`profile-group` / `vp-profiles` / `as-profiles` 回 `No such node` 時視為空設定，不中斷特徵碼快照更新。
10. **抽屜按需單筆查詢（`show threat id <ID>`）**：成功寫入 `done` 並快取 1 天 + 設 10 秒全域限流；快取命中（含負快取）不碰 PA；限流 / 暫停 / CPU 超標均標 `rejected`；查無（空結果或 `No such node`）標 `not_found` 並快取 1 天；非法 ID 標 `failed` 不碰 PA 且不扣限流。
11. **設定驗證**：`PA_SIGNATURE_ENABLED` 預設關閉、金鑰回退順序（`PA_SIGNATURE_API_KEY_FILE` → `PA_POLICY_API_KEY_FILE` → `PA_API_KEY_FILE`）、正式區禁止明文金鑰、`PA_SIGNATURE_MINUTES` 下限 10、`PA_SIGNATURE_MAX_MGMT_CPU` 上限 50、`PA_SIGNATURE_HTTP_TIMEOUT_SECONDS` 5–120。

## 4. 可能問題與潛在風險

1. **測試環境既有警告（非本次變更引起）**：
   - `anyio/pytest_plugin.py`：`PytestRemovedIn10Warning`（pytest 9.2 與本機 Python 3.14 套件相容警告；CI 使用 Dockerfile 固定 Python 3.12 與 `requirements-dev.txt`）。
   - `tests/test_poller.py::test_tls_verification_on_by_default`：`pan/xapi.py:116` 的 `DeprecationWarning: ssl.PROTOCOL_TLS is deprecated`。
2. **合併後 `netops-pa` 容器重建會中斷 PA-560 Syslog 連線**：
   - 相關檔案：`deploy/ci-netops-pa.sh`、`pa-collector/`、`deploy/docker-compose.yml`。
   - 影響：本批動到 `pa-collector/` 與 `deploy/docker-compose.yml` 的 `netops-pa` 區段，合併進 `develop` 部署測試區時會觸發重建 `netops-pa`，PA-560 TRAFFIC Syslog 不會自動重連，需配合網通對 `netops-syslog` 重新 Commit（`docs/PA-FORWARDING-SPEC.md` F.3）。
3. **實際 3.5 萬筆資料寫入 Redis 記憶體與序列化時間**：
   - 相關檔案：`pa-collector/netops_pa/signatures.py` L585–L606（`SIG_ITEMS_VULN`、`SIG_ITEMS_SPYWARE`）。
   - 說明：TS-0 實測原始 XML 約 14.1 MB（25,450 + 9,566 筆），正規化 JSON 預估約 8–11 MB，對 `netops-redis`（`maxmemory 2gb`）佔比低，但仍建議於測試區開啟 `PA_SIGNATURE_ENABLED=1` 後以 `redis-cli MEMORY USAGE` 實測實際佔用與 `durationMs`。
4. **Profile Group 變更更新時機**：
   - 相關檔案：`pa-collector/netops_pa/signatures.py` L488–L550。
   - 說明：依計畫書 §1.2 #13（「每 30 分鐘只讀 `show system info`」），`profile-group` 與 VP / AS profile 只在版本變動、無快照或手動更新時重讀。若網通修改 Profile Group 但 PA 尚未釋出新特徵版本，需點「手動更新」才會立即反映到規則覆蓋。
