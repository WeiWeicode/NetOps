### 新增單元測試涵蓋範圍

#### 後端（`backend/test/unit/pa-signature.test.ts`）
1. **核心純函式（`core.ts`）**：
   - `extractThreatId`：解析 `名稱(ID)`、`名稱 (ID)` 與純數字 ID，拒絕無數字或非數字字串。
   - `diffSignatures`：精準比對精簡索引與新清單，輸出 `added`、`changed`（含欄位異動前後值 `severity`、`defaultAction`、`cves` 等）、`removed`。
   - `computeCoverage`（TS-Q5）：針對啟用中 `action=allow` 規則判斷是否有掛 VP / AS（直接掛或經 vsys1 Profile Group 展開）；忽略 `deny` 與 `disabled` 規則；群組不存在或讀不到 `profiles` 快照時標為 `unknown`（不當成有防護）；輸出 `unprotectedRules` 供命中比對標註。
2. **版本歷史 Store（`infra/store/pa-signature.ts`，D1 / D2）**：
   - 依 D1 寫入順序（1. `history/<threatVersion>.json` → 2. `index.json` → 3. `latest-index.json.gz` → 4. 清理超出保留份數的舊差異檔）原子落地。
   - D2 持久基準日 `baselineAt` / `baselineVersion` 一旦由第一份寫入即固定，不因滾動淘汰或 Redis 7 天 TTL 過期而重設。
   - 版本檔名白名單（拒絕 `../evil` 等路徑穿越）。
3. **API、D1/D2 流程與外部依賴降級**：
   - Redis 尚無快照或斷線時，清單與狀態皆回 200 `available: false`（不回 5xx）；ClickHouse 查詢失敗回 424 `NETOPS_PA_SIGNATURE_CH_UNAVAILABLE`（不回 5xx）。
   - OpenAPI 驗證：確認所有路由均具 `operationId`、`summary`、`description`、`x-permission`、`x-gherkin`；TS-Q8 無 IP 路由（`/v1/pa-signature-hit-queries`）綁 `netops.pa-signature.read`，含 IP 路由（`/v1/pa-signature-hit-ip-queries`）綁 `netops.pa-log.read` 並設 `x-audit-level: meta`；規則覆蓋（`/v1/pa-signature-coverage`）綁 `netops.pa-policy.read`。
   - D2 基準版（`added=0`、`isNew=false`）→ D1 版本更新差異（`added` / `changed` / `removed` 與分頁篩選）→ `days` 只接受 7 / 30 / 90（14 回 400），基準日晚於「今天 − days」時回 `since = YYYY-MM-DD`。
   - 單筆查詢 `GET /v1/pa-signatures/:id`：快照命中（含 `changes[]`）、1 天快取命中、未命中送 202 `{ lookupId }` 給收集器按需查 `show threat id`、限流回 429 `NETOPS_PA_SIGNATURE_COOLDOWN` + `Retry-After`、輪詢結果 `GET /v1/pa-signature-lookups/:lookupId` 強制擁有者隔離（別人回 404）。
   - 命中比對：無 IP 路由絕不回 `topSrc` / `topDst`；含 IP 路由回前 10 `topSrc` / `topDst`；標註 `ruleDetails[].unprotected`；90 天強制轉 202 工作模式並支援輪詢與冪等 204 `DELETE`。
   - 手動重新整理：`202` / `429` 冷卻 + `Retry-After` / `409` 未啟用 / `424` Redis 斷線。
4. **背景排程同步與中途失敗復原（D1）**：
   - 未呼叫任何頁面 API 時，背景排程自動建立基準版並於版本變更時寫入差異檔；模擬「第 1、2 步完成、第 3 步更新 `latest-index.json.gz` 前崩潰」後，下一輪排程重跑冪等復原，不重複紀錄版本且保留原始 `baselineAt` 與完整差異。
5. **戰情室整合（`warroom.ts`，計畫 §5.4）**：
   - `GET /v1/pa-live/warroom` 與 `GET /v1/pa-live/risk` 命中近 30 天新增特徵碼時附帶選填欄位 `newSignatureHits`，無命中（只有基準特徵）時省略。
6. **Claude 審查修正（P1 / P2）**：
   - **P1**：以計數假 store 驗證版本未變時連續呼叫 `list` / `versions` / `get` 均 0 次呼叫 `readLatestIndex()`；版本更新時讀一次並正確產出差異；程序重啟後首次核對讀 1 次、後續 0 次。
   - **P2**：有歷史但刪除或損壞 `latest-index.json.gz` 後執行 `sync()`，驗證新版本標記 `rebuilt: true`、`isBaseline: false`、`added: 0`、`baselineAt` 不變、記 `warn` 日誌（不含檔案路徑與特徵內容）、`isNew: false` 且不計入新特徵碼 / 戰情室、`versions` / `diffs` / `list` / `get`（`changes[]`）皆帶 `rebuilt`；下一版恢復正常比對。

#### 前端（`frontend/test/paSignature.test.ts`、`frontend/test/paSignatureDrawer.test.ts`）
1. **`usePaSignature`**：清單分頁與 `days`（7 / 30 / 90）/`since`；依 `can(API.paLogRead)` 分流無 IP / 含 IP 命中路由、依 `can(API.ipNameRead)` 決定是否查 `lookupIps`；202 工作輪詢至完成；規則覆蓋受 `netops.pa-policy.read` 控管；手動重新整理受按鈕權限與冷卻處理；P2 `isDiffUnavailable` / `currentVersionRebuilt` / `diffUnavailable` / `diffUnavailableMessage`。
2. **`usePaSignatureDrawer`**：`extractThreatId` 解析；權限控管；快照 200 直接開抽屜；202 按需查詢開抽屜並輪詢至 `done` / `not_found` / `rejected`；429 限流提示；較新 `show()` 或 `close()` 取消舊請求；P2 `hasRebuiltChanges`。

## 4. 可能問題與潛在風險

1. **ClickHouse 命中查詢在實測資料量下的查詢效能（計畫 §5.1）**：
   - 相關檔案：`backend/src/infra/clickhouse/reader.ts`（`signatureHitCounts`、`signatureHits`）。
   - 說明：以 `extract(threat_name, '\\(([0-9]{1,10})\\)$')` 與純數字回退方式比對 `pa_threat_logs`（`log_type = 'threat'`）。30 天內預設同步等 8 秒（路由 `x-timeout-ms: 15000`），超過自動轉 D6 工作模式（上限 60 秒）；90 天直接轉工作模式。建議上測試區後以實際資料量確認 `signatureHitCounts`（30 天清單快取 5 分鐘）耗時。
2. **TS-Q8 權限分拆為雙路由**：
   - 相關檔案：`backend/src/modules/pa-signature/routes.ts`、`frontend/src/composables/usePaSignature.ts`。
   - 說明：因 Gateway `X-Internal-Token` 僅帶角色、不帶個別 API 權限清單，且 BFF 每條路由只綁定一個 `x-permission`，故將「命中比對（不含 IP）」放在 `POST /v1/pa-signature-hit-queries`（`netops.pa-signature.read`），「命中比對（含前 10 IP）」放在 `POST /v1/pa-signature-hit-ip-queries`（`netops.pa-log.read`、`x-audit-level: meta`），讓 BFF 於後端強制控管 IP 顯示，不依賴前端隱藏。
3. **規則覆蓋路由權限**：
   - 相關檔案：`backend/src/modules/pa-signature/routes.ts`（`GET /v1/pa-signature-coverage`）。
   - 說明：單條路由僅能宣告一個 `x-permission`，此路由宣告 `netops.pa-policy.read` 以保護 PA 安全規則資料（`netops-admin` 與 `netops-viewer` 皆同時具備 `pa-signature-page.read` 與 `pa-policy-page.read`；若 GigaItApp 個別指派角色僅具特徵碼頁而無安全規則權限，前端不呼叫且 BFF 會回 403）。
4. **敏感設定變更**：
   - `deploy/gateway-rbac.yaml`：新增 `netops.pa-signature-page.{read,refresh,ai}` 與角色指派（admin 三項、viewer 唯讀 + AI）。
   - `deploy/kb-backup/backup.sh`：將 `pa-signature` 加入每日 NAS 資料備份清單 `DATA_DIRS`。
