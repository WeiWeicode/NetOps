### 新增單元測試涵蓋範圍

#### 後端（`backend/test/unit/pa-signature-ai.test.ts`）
1. **高危挑選與上限 50 筆（`pickHighRiskSignatures`、`buildSignatureAiContext`）**：
   - 只挑新增高危（`critical` / `high`），中 / 低 / 資訊只計入總數不展開明細。
   - 排序規則：`有命中 > 無命中` → `critical > high` → 命中數降冪 → ID 升冪。
   - 超過 50 筆新增高危特徵（測試 70 筆 / API 65 筆）時只送前 50 筆，且明確告知總數與省略筆數（`truncatedSignatures: true`、`sentSignatures: 50`）。
2. **嚴格去識別化驗證（不含 IP、姓名、原始 log）**：
   - 測試資料刻意寫入 IP 對照表（`10.10.1.50` / `王小明` / `資訊處`）、知識庫筆記（含 IP 與姓名）、含人名與 IP 的安全規則（`Allow_王小明_10.10.1.50`、說明 `林美玲申請`、使用者 `gsmc\linml`）、ClickHouse 威脅 log（`src`/`dst`/`natSrc`/`srcUser`/`url`/`filedigest`）與 IPv6 流量。
   - 攔截送往 `fakeAiHost` `/v1/chat/completions` 的完整訊息（system + user），驗證不含任何 IPv4 / IPv6、姓名、部門、AD 帳號、規則名稱、原始 log URL / digest、IP 對照表或知識庫段落。
3. **「AI 建議,需網通確認」只放開頭**：
   - 提示詞明確要求不輸出 PA 指令或 API 呼叫，且說明畫面開頭已固定標示「AI 建議，需網通確認」，回答內文與結尾不重複免責警語。
4. **邊界與外部依賴降級**：
   - `days` 僅接受 `7 / 30 / 90`（預設 `30`，`14` 回 `400 VALIDATION_FAILED`）。
   - 無快照回 `404 NETOPS_PA_SIGNATURE_UNAVAILABLE`、Redis 故障回 `424 NETOPS_PA_SIGNATURE_UNAVAILABLE`、未設 `LLM_URL` 回 `409 NETOPS_AI_DISABLED`（皆不回 5xx）。
   - ClickHouse 故障時不回 5xx，仍可正常串流並於 `meta` 與提示詞明確標示 `hitsAvailable: false` / `appsAvailable: false` / `partial: true`。
   - 基準版（0 筆新增）、歷史不足（`since`）、精簡索引重建（`rebuilt: true`）、快照過期（`stale: true`）皆正確帶入 `meta` 與提示詞。

#### 前端（`frontend/test/paSignature.test.ts`）
- 驗證 `PA_SIGNATURE_AI_DISCLAIMER` 內容、`usePaSignature().runAi()` 權限控管與送出 `{ kind: 'pa-signature', params: { days } }`，以及 `explainNotices` 針對 `pa-signature` 各種不完整狀態的提示文字。

## 3. 失敗項目

- 單元測試、型別檢查與建置皆 **0 失敗**。
- `backend/` `npm run test:int` 因本機未啟動一次性 ClickHouse / Redis 測試容器而未通過前置環境檢查（同 TS-2）。

## 4. 可能問題與潛在風險

1. **ClickHouse `topApps` 與 `signatureHits` 查詢時間**：
   - 相關檔案：`backend/src/infra/clickhouse/reader.ts`（`topApps`）、`backend/src/modules/pa-signature/service.ts`（`forAi`）。
   - 說明：`topApps` 查每小時彙總表 `pa_traffic_hourly_app`（30 天）；`signatureHits` 僅針對前 50 筆中有命中的特徵 ID 查詢且強制 `includeIps: false`（不掃 IP 欄位）。如遇 ClickHouse 逾時或故障會自動降級標示缺漏而不回 5xx。
2. **權限對應（同 PR-5 設計）**：
   - `POST /v1/ai/explanations` 沿用既有路由 `x-permission: netops.ai.use`；畫面按鈕於 TS-2 已在 `deploy/gateway-rbac.yaml` 登記 `netops.pa-signature-page.ai`（`includes: [netops.ai.use, netops.pa-signature.read]`）。
3. **測試區實跑確認**：
   - 待需求方於測試區開啟 `PA_SIGNATURE_ENABLED=1` 並合併本 MR 後，於測試區實跑一次 `kind: pa-signature` 驗證真實 LLM 輸出品質（計畫 §8）。
