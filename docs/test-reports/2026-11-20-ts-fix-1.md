### 新增測試涵蓋範圍

1. **F1-a 收集器（`pa-collector/tests/test_signatures.py`）**：
   - `parse_threat_id`：驗證 PA 回傳 `name=Unknown`、`subtype=Unknown`（不分大小寫、含前後空白）且 `severity` / `description` 為空時回傳 `None`；若有 `severity` 或 `description` 則不誤判。
   - `SignatureWorker.run_one_lookup`：驗證重現案例 `109010004`（`Proxy:hola.org`）寫為 `not_found` 與負快取；既有舊 1 天快取含 `found: true` + Unknown 佔位時，直接回 `not_found`、不打 PA、不刪除或改寫 Redis 快取。
2. **F1-b / F1-c 後端（`backend/test/unit/pa-signature.test.ts`）**：
   - `isUnknownLookupResult`：驗證大小寫與空白正規化、含 `severity`/`description` 時為 `false`。
   - 舊 1 天快取（`netops:pa:sig:lookup:cache:109010004` 存 `found: true` 且 item 為 Unknown 佔位）：`GET /v1/pa-signatures/109010004` 回 200 `found: false`、`message` 含「本機特徵庫查無…」與 ClickHouse 近 30 天命中數 `hits30d`，且**不刪除、不寫入 Redis 快取**。
   - `GET /v1/pa-signature-lookups/:lookupId`：驗證 `status: 'done'`、`status: 'not_found'` 及舊 `done + Unknown` 皆回傳 `hits30d`（ClickHouse 有資料回命中數、失敗回 `null` 且不回 5xx），不寫 Redis。
3. **F1-d 前端（`frontend/test/paSignatureDrawer.test.ts`、`frontend/test/paSignature.mount.test.ts`）**：
   - 200 快取查無（含舊 Unknown 快取轉 `not_found`）與 202 按需查無皆開啟抽屜，顯示「本機特徵庫查無(可能是病毒 / WildFire / 自訂特徵)」與「近 30 天命中：1,408 筆」（ClickHouse 失敗為 `null` 時顯示「無法取得（ClickHouse 未連線）」）。
   - 202 按需查到（`done`）正確將 `job.hits30d` 帶入抽屜顯示命中數（不再固定顯示「無法取得」）。
4. **F2 AI 摘要措辭（`backend/test/unit/pa-signature-ai.test.ts`）**：
   - 驗證新增高危特徵 0 筆（基準版或僅有中低危新增）且 ClickHouse 正常時，送給模型的命中段落包含「近 30 天沒有新增高危特徵，因此沒有新特徵命中可統計」（7 天對應「近 7 天…」），不再送出易誤導的「0 / 0 個有命中，共 0 筆」，並加註不代表整體環境沒有既有威脅特徵命中。
   - 驗證 `PA_SIGNATURE_PROMPT` 明確規定不得寫成整體環境「沒有任何命中」。
